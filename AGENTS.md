# AGENTS.md

Guidance for coding agents working in this repository.

- Read `README.md` and `docs/` before changing code. Plans live in `docs/plans/`.
- Run `npm test` and `npm run lint` before every commit; Swift code: `swift test --package-path Packages/HermesAdapter --skip PerfTests` and the Xcode scheme `HermedBots` (probe classes skipped). Performance probes are a separate pass on scheme `HermedBotsPerf`, documented in `docs/perf-probes.md`.
- Work on a branch and open a pull request against `main`; never push to `main` directly.
- No infrastructure information in the repository, commits, issues, pull requests or comments: no local paths (`/Users/<name>`, `/home/<name>`), host names, internal domains (`*.local`), private IPs, internal ports, machine names, Apple Team ID or signing identity, personal e-mail addresses. Redact before posting (`~`/`<HOME>`, `<HOST>`, `<IP>`). The `infra-guard` workflow enforces this.
- Evidence, raw logs and screenshots stay on the machine that produced them (see `.gitignore`); pull requests cite a redacted summary only.
- Machine-specific or operator-specific instructions do not belong in this repository.

## Rule to mechanism

| Rule | Mechanism that applies it |
| --- | --- |
| Frozen versions and approved distribution configuration | `scripts/distribution.js`, `test/distribution/release.test.js`, and `.github/workflows/release.yml` job `preflight`. |
| No Cursor attribution, no Co-authored-by, no authored Open in Cursor footer | `.githooks/commit-msg`, `scripts/check-pr-attribution.js`, job `pr-attribution`, and `scripts/squash-merge.js` with an empty squash body that also strips every Co-authored-by line with no allowlist. `scripts/check-pr-attribution.js` strips a matching host-injected trailing PR footer (`authoredPrBody`) before it scans the PR body, so that host footer is allowed. Commit messages and authored briefing text still fail on `Co-authored-by`, `Open in Cursor`, and `cursor.com/agents`. `scripts/install-git-hooks.js` copies the hook scripts into `hermed-bots-hooks`. `git worktree add --no-checkout` then `git checkout`, and a linked worktree after the primary directory is renamed, can skip the hook. Those two Git layouts are already named here. CI still reads stored messages. |
| No Co-authored-by trailer on main | `.githooks/commit-msg` via `scripts/check-commit-msg.js` rejects every Co-authored-by line, with no allowlist. `.cursor/hooks.json` runs `.cursor/hooks/deny-coauthored-by.js` before every agent shell command (`matcher` `*`). The script denies Co-authored-by trailers, including quoted `-m` and `--trailer` values. `scripts/squash-merge.js` strips every Co-authored-by line from the squash commit message, with no allowlist. Tests: `test/commit-msg-hook.test.js`, `test/deny-coauthored-by.test.js`, `test/squash-merge.test.js`. |
| Marked `PASS` or `PASS+NOTES` with `<!-- dev-lead-verifier -->`, posted by `app-pilote-verifier[bot]`, on the head SHA or on a prior SHA of the same PR whose `git patch-id --stable`, `git patch-id --verbatim` and exact replay tree against the PR base all match the head | `scripts/verdict-gate.js` and `.github/workflows/verdict-gate.yml`. The job computes the ids and the replay tree (`git merge-tree`) from git objects (never from a comment or PR file) and runs the base-branch copy of the script. The cited SHA must appear in this PR's commits or timeline and must not be reachable from the PR base. Empty diffs do not count. A later marked `FAIL` on the head or on the same patch-id wins. Docs-or-rules does not skip. A marked comment from `cursor[bot]` is an informative signal only and never turns the gate green. |
| Verdict comment is not the PR author | `scripts/verdict-gate.js` compares the marked comment login to the PR author login. |
| Direct push to `main` | `.githooks/pre-push` via `scripts/check-pre-push.js`. After a GitHub push, `scripts/check-main-push.js` and `.github/workflows/main-push.yml`. Branch protection cannot be set from this token. |
| PR body lists `bc-` UUID ids under `## Agents` | `scripts/check-pr-attribution.js` |
| Program plans pass `check-plan.mjs` | `scripts/check-plans.js` and `.github/workflows/check-plans.yml` |
| No change to `.claude/`, `.codex/` or `.mcp.json` in a PR | `scripts/check-protected-paths.js` and `.github/workflows/protected-paths.yml`. The workflow triggers on `pull_request_target`, so GitHub reads its definition from the base branch and a pull cannot disable the job by editing the file. The job checks out the base branch, runs the base-branch copy of the checker, and fetches the pull head as git objects only (no checkout of the pull). |
| No change to verdict-gate or to the protected-paths workflow/checker without verifier approval | Same job. `GATE_FILES` is `.github/workflows/verdict-gate.yml`, `.github/workflows/protected-paths.yml`, `.github/workflows/anti-parallel.yml`, `scripts/verdict-gate.js`, `scripts/check-protected-paths.js` and `scripts/check-anti-parallel.js`. Those paths fail the check unless `app-pilote-verifier[bot]` applied `gate-change-approved` after the current head (`labeled.created_at` strictly after the latest `head_ref_force_pushed.created_at` or `committed.committer.date` in the issue timeline), not from the label list on the pull. Branch protection required checks are outside the repository. |
| Latest OS, SDK, language, and tool versions, no backward compatibility (macOS 27+ here) | The independent verifier checks deployment targets, SDK and toolchain versions, and any new fallback at each PR. Review. |
| No infrastructure information in diffs, PR bodies, pushes or comments | `scripts/infra-guard-ci.js`, `test/infra-guard-ci.test.js`, and job `scan` in `.github/workflows/infra-guard.yml` |
| une mise à jour remplace l'app, jamais de doublon | `scripts/sparkle-update-proof.sh` (`count_hermedbots_copies` / `prove_single_copy`, `single-copy pass` or `single-copy fail` on `SPARKLE-PROOF*`), `test/distribution/sparkle-update.test.js`, and the mandatory post-update check in `.cursor/skills/verify-hermed-bots/` |
| One verifier per head SHA and one executor per PR | Concurrency group `verdict-gate-<pr>` in `.github/workflows/verdict-gate.yml`, `verifier-<pr>` in `.github/workflows/anti-parallel.yml`, and `executor-<pr>` in `.github/workflows/ci.yml` (`cancel-in-progress: false`). Groups use the pull number only (`github.event.pull_request.number || github.event.issue.number`). `scripts/check-anti-parallel.js`, `test/check-anti-parallel.test.js`, and job `anti-parallel` fail closed when more than one marked `VERDICT` comment (`<!-- dev-lead-verifier -->`) from an approved verifier (`app-pilote-verifier[bot]` with type `Bot`) cites the head SHA, when a second verifier workflow run is in progress or queued for that SHA, or when PR commits name more than one `bc-` agent identity in an overlapping authored-at window. The job recomputes the full verdict on `pull_request` and `issue_comment`. Executor commits come from `git log` when that range is readable, otherwise from the pull commits API. That API stops at 250 commits; a list of 250 items, a declared `commits` count of 250 or more, or a count that does not match the loaded list fails closed. |
